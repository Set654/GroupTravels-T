# Авиамодуль «Т-Путешествие»

Внутренний Python/FastAPI-сервис авиапоиска по §3.5 обновлённого SRS.
C# вызывает Python по HTTP, получает нормализованные предложения и сам
управляет доступом к поездкам и ручным сохранением выбранного рейса.

Рабочий маршрут: `GET /internal/flights/search`.
Данные кэшированные, цена и наличие на момент покупки не подтверждаются.

## Установка

Проверено с Python 3.12. PowerShell из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/configure_local.py
```

Скрипт создаёт `.env` при отсутствии и генерирует отдельный
`INTERNAL_API_KEY`, если его ещё нет. Значение ключа не выводится, существующий
ключ и токен не заменяются. Заполните `TRAVELPAYOUTS_TOKEN` в своём
`.env`. Для доступа из C# настройте там тот же внутренний ключ, не токен провайдера.
Переменные окружения имеют приоритет над `.env`; пример настроек —
[.env.example](.env.example). Реальный файл с секретами не коммитится.

Сервис откажется запускаться, если нет ключей, справочника или настройки невалидны.

## Запуск HTTP-сервиса

```powershell
.\.venv\Scripts\python.exe -m uvicorn api:create_app --factory --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

- `http://127.0.0.1:8000/health` — локальная проверка жизни приложения.
- `http://127.0.0.1:8000/docs` — Swagger UI. В Authorize укажите внутренний ключ.
- `http://127.0.0.1:8000/openapi.json` — схема. В репозитории: [docs/openapi.json](docs/openapi.json).

Для другой машины настройте адрес привязки, закрытую сеть и HTTPS/прокси.
Сервис предназначен для вызова основным backend, не напрямую браузером пользователя.
JWT и доступ к поездке проверяет C#. Внутренний ключ передаётся только между серверами.

## Запрос и ответ

```http
GET /internal/flights/search?origin=MOW&destination=LED&departureDate=2026-12-15
X-Internal-Api-Key: <секрет из конфигурации>
```

Выберите дату, которая ещё не прошла. HTTP-интерфейс принимает два разных
известных IATA-кода и точную дату вылета, ищет в одну сторону и возвращает
до 10 предложений по возрастанию цены. Проверка прошедших дат использует
`SEARCH_TIMEZONE` (по умолчанию Europe/Moscow). Месяцы, обратная дата,
названия городов, `tripId`, неизвестные и повторяющиеся параметры отклоняются.

Результат: `source`, `dataType`, `currency` и `flights[]`.
В каждом предложении: маршрут, дата/время, перевозчик, номер рейса, цена в RUB,
пересадки, длительность и полная ссылка Aviasales. Отсутствующие необязательные
поля равны `null`. Пустой кэш — 200 и `flights: []`.
Сбой провайдера возвращается как ошибка, а не как пустая выдача.

Примеры и точные правила: [контракт интеграции](docs/INTEGRATION.md),
[искусственные ответы](examples/responses/search-success.json).
Стас подтвердил контракт, заголовок ключа, timeout C# 30 с, отключение редиректов,
отсутствие offerId и все поля с null для отсутствующих сведений. Для интеграционного
тестирования также приняты Europe/Moscow (временная проверка прошедших дат),
connect/read timeout 3/10 с и 4 параллельных поиска на процесс. departureDate
сохраняет смысл даты в месте отправления. Настройка развёртывания и совместный
прогон с основным C# backend ещё предстоят.

## Пример клиента C#

[examples/csharp/FlightSearchClient.cs](examples/csharp/FlightSearchClient.cs)
содержит типизированный адаптер и DTO с `decimal`, `DateOnly`,
`DateTimeOffset?`. Для запуска примера нужен .NET 8 или новее и переменные
`INTERNAL_API_KEY`, `FLIGHTS_BASE_URL` (по умолчанию http://127.0.0.1:8000/).

```powershell
dotnet run --project examples/csharp/FlightSearchExample.csproj -- 2026-12-15
```

C# не читает Python-файл `.env` автоматически: ключ нужно настроить в
окружении/секретах C# отдельно. Пример не реализует JWT, маршруты основного API
и запись в БД. Эти части остаются за основным backend.

## Тесты и обновление схемы

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe scripts/export_contract.py
```

Проверка C# адаптера через настоящий локальный HTTP-сервер и искусственного
провайдера, без реального токена (нужен .NET SDK):

```powershell
.\.venv\Scripts\python.exe scripts/check_csharp.py
```

Тесты не требуют реального токена и подменяют сетевые запросы провайдера.
Проверяются HTTP-контракт, ключ, параметры, ответы и ошибки, сортировка,
часовые пояса, ссылки, ограничение параллелизма, CLI и запись временных файлов.
Обновление OpenAPI и искусственных примеров выполняется без сети и реальных ключей.

Справочник кодов включён в `data/iata_locations.json`, при обслуживании релиза
его можно обновить: `python scripts/update_iata.py`. Это отдельный реальный
запрос открытых справочников, не часть обычного поиска или тестов.

## Структура

| Файл | Обязанность |
| --- | --- |
| `api.py` | HTTP, ключ, статусы, OpenAPI |
| `service.py` | Проверка запроса MVP → получение → нормализация → сортировка |
| `travelpayouts.py` | Фиксированный внешний API, таймаут, проверка конверта ответа |
| `normalization.py` | Базовые поля и полное предложение для HTTP |
| `booking_links.py` | Проверка и построение ссылок без открытия внешнего URL |
| `validation.py`, `catalog.py` | Правила входа и локальные коды городов/аэропортов |
| `schemas.py`, `settings.py`, `errors.py` | Схемы, настройки и типы ошибок |
| `main.py` | Сохранённый учебный CLI и JSON для локальной отладки |

## Сохранённый терминальный клиент

```powershell
.\.venv\Scripts\python.exe main.py --origin MOW --destination LED --departure-at 2026-12
.\.venv\Scripts\python.exe main.py --origin MOW --destination LED --departure-at 2026-12-10 --return-at 2026-12-20 --output tickets.json
```

CLI и `main.get_cheap_bilets()` продолжают возвращать исходные словари
Travelpayouts и поддерживают месяцы/туда-обратно. Их более широкий учебный
интерфейс не является HTTP-контрактом MVP. Непустой результат сохраняется только
при `--output`; указанный файл заменяется. Пустая выдача файл не меняет.
`tickets.json` — отладочный файл, не пользовательское хранилище.

## Граница MVP

Реализован Python-поиск для подключения к C#. Ручное добавление записи таймлайна,
проверка пользователей, хранение и отображение предупреждения о кэшированной цене
относятся к C#/frontend. Их готовность этим репозиторием не подтверждается.

Links API, SubID, Statistics API и автоматическое подтверждение покупки —
отдельный расширенный этап §3.6. Отели, развлечения и OCR — другие модули.
Исторические эксперименты в `litter/` не участвуют в работе HTTP-сервиса.
