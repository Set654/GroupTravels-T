## Граница применения

§1–2 на странице 1 описывают **основной публичный .NET API и поведение React**.
Публичный формат — ProblemDetails с текстовым полем code. Пример содержит
type/title/status/code; title/detail не должны раскрывать технические данные.
Внутренний Python продолжает возвращать code/message: отдельного требования
перевести его ответы в ProblemDetails в файле нет. Преобразование делает C#.

## Авиапоиск: страницы 3–4, §4–5

| Ситуация | Публичный результат C# по каталогу |
| --- | --- |
| Python 200 с flights: [] | 200, пустая выдача, без ошибки |
| Python 400, неправильные параметры | 400 INVALID_SEARCH_PARAMETERS |
| Python 401, неверный межсервисный ключ | 502 FLIGHT_INTEGRATION_AUTH_ERROR; пользователь не разлогинивается |
| Сбой Python/Travelpayouts | 502 FLIGHT_PROVIDER_ERROR |
| Ответ Python нечитаем или нарушает JSON-контракт | 502 INVALID_FLIGHT_SERVICE_RESPONSE |
| Нет соединения с Python | 503 FLIGHT_SERVICE_UNAVAILABLE |
| Превышено время ожидания | 504 FLIGHT_SEARCH_TIMEOUT |
| Python вернул 503 | 503 FLIGHT_SERVICE_UNAVAILABLE |
| Python вернул 504 | 504 FLIGHT_SEARCH_TIMEOUT |
| Неожиданная ошибка самого C# вне зависимости | 500 INTERNAL_ERROR |

Различать две границы некорректного JSON: если Python отверг ответ Travelpayouts
и вернул корректную ошибку 502, это FLIGHT_PROVIDER_ERROR. Если C# не может
прочитать/проверить ответ самого Python — INVALID_FLIGHT_SERVICE_RESPONSE.
Внутренний 500 Python относится к сбою зависимости и не должен автоматически
обозначаться публичным 500 самого C# API.

## Сверка с текущим кодом

- api.py уже возвращает внутренние 400/401/500/502/503/504 и code/message;
  пустая выдача — 200. Для указанного публичного каталога менять это не требуется.
- Внутренний 401 остаётся 401: его преобразование в публичный 502 выполняет C#.
- Пример FlightSearchClient.cs хранит внутренний статус Python в исключении,
  публичный контроллер в этом проекте не реализован. Передача этого статуса
  frontend без преобразования не соответствует каталогу.
- Метод InvalidResponse() примера C# сейчас использует FLIGHT_PROVIDER_ERROR,
  а каталог для некорректного ответа Python вводит отдельный
  INVALID_FLIGHT_SERVICE_RESPONSE. Резервная обработка нечитаемой ошибки также
  требует явной классификации на C# стороне. Пример пока не приведён к этим
  новым публичным кодам; основной C# backend команды здесь не проверен.

## Условные решения и прочие модули

- 422 в §3 указан только «если команда выберет 422». Авиапоиск сохраняет 400
  для некорректных параметров; общей команды заменить его на 422 нет.
- Скрытие чужой поездки через 404 вместо 403 предложено как общая политика.
  Это ответственность публичного C#, не проверка прав в Python.
- SMS, профиль, поездки, расходы, долги, OCR и импорт URL перечислены для полноты
  основного API; новых задач реализовать их в авиамодуле из файла не следует.

## Что проверить совместно

После получения ветки основного C# backend проверить не только HTTP-статус,
но и публичный ProblemDetails/code, соответствие status реальному HTTP-статусу,
отсутствие секретов/внутренних сообщений и отсутствие разлогинивания при
неверном внутреннем ключе. Отдельно воспроизвести испорченный ответ Python,
Python 500/503/504 и сбой самого C# вне вызова зависимости.
