# Авиапоиск: актуальный интерфейс и прежний черновик

Актуально на 7 ноября 2026. Контракт авиапоиска появился в §3.5 обновлённого
SRS (13 страниц). Реализованный Python-интерфейс описан в
[INTEGRATION.md](INTEGRATION.md), машинная схема — [openapi.json](openapi.json).

## Текущий сценарий

1. Пользователь задаёт IATA-коды и точную дату; C# проверяет пользователя/поездку.
2. C# вызывает GET /internal/flights/search.
3. Python возвращает source, dataType, currency и нормализованный flights[].
4. Пользователь выбирает предложение и переходит по исходной ссылке Aviasales.
5. По желанию пользователь вручную сохраняет рейс через публичный C# маршрут.
   C# управляет Trip_Activity и scheduledAt в UTC/null.
6. Запись не доказывает оплату, автоматического расхода нет.

## Что изменилось относительно первоначального примера

Прежние offers/timeline_entry, денежная строка и start_time/end_time были
предложениями до получения обновлённого SRS. Они не реализуются как текущий
HTTP-ответ. Названия городов и месяцы не входят в базовый HTTP-запрос; существующий
терминальный клиент сохраняет собственные более широкие параметры.

## Оставшиеся согласования

Стас подтвердил контракт поиска, X-Internal-Api-Key, timeout C# 30 с,
отключение редиректов, отсутствие offerId и все поля с явным null.
Предложение сохранять без ссылки и публичный JSON ошибок требуют решения
Матвея. Рабочая C# ветка интеграции пока не подтверждена; оставшиеся вопросы
перечислены в [чеклисте](INTEGRATION_CHECKLIST.md).

SubID/Statistics и автоматическое добавление купленного билета — расширенный
этап §3.6; готовность поиска не подтверждает готовность этого сценария.
