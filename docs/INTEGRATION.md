# Авиапоиск Python ↔ C#: реализованный интерфейс MVP

Дата: 7 ноября 2026. Основа — §3.5 обновлённого `SRS_T-travel (1).pdf`
(13 страниц). Код Python реализован; совместный прогон с основным C# backend
ещё предстоит. По переданному пользователем ответу Стаса согласованы контракт
поиска, X-Internal-Api-Key, таймаут C# 30 с, отключение редиректов, отсутствие
offerId и присутствие всех полей с null для отсутствующих необязательных сведений.
Ниже отдельно отмечены вопросы к Матвею и настройки, ещё требующие подтверждения.

Дополнительно Стас подтвердил текущие параметры Python для интеграционного
тестирования: Europe/Moscow, connect 3 с, read 10 с и 4 параллельных поиска.
Europe/Moscow — временное правило проверки прошедшей даты, не часовой пояс
всех рейсов. Календарная departureDate относится к месту отправления.

## Ответственность

Frontend вызывает публичный .NET API. C# проверяет JWT, поездку и права участника,
затем вызывает Python. Python получает кэшированные предложения, проверяет и
нормализует их. C# вручную сохраняет выбранный пользователем рейс через свой
`POST /api/trips/{tripId}/activities` согласно §3.5.4. Python не принимает `tripId`,
не пишет в PostgreSQL, не подтверждает оплату и не создаёт расход.

## Запрос к Python

```http
GET /internal/flights/search?origin=MOW&destination=LED&departureDate=2026-12-15
X-Internal-Api-Key: <общий секрет C# и Python>
```

- Ровно три обязательных query-параметра. Неизвестные и повторяющиеся параметры
  отклоняются; `return_at`, `tripId`, месяцы и произвольные названия городов не входят
  в этот HTTP-интерфейс. Один запрос ищет перелёт в одну сторону, до 10 предложений.
- Коды очищаются от пробелов по краям, переводятся в верхний регистр, проверяются
  по локальному справочнику городов/аэропортов Travelpayouts. Коды должны различаться.
- Дата строго `YYYY-MM-DD`, не раньше сегодняшнего дня в `SEARCH_TIMEZONE`
  (по умолчанию `Europe/Moscow`). Сегодня разрешено; время уже прошедших рейсов
  текущего дня отдельно не фильтруется. Календарная дата относится к месту вылета.
  Применение Europe/Moscow согласовано как временное правило интеграционных тестов;
  оно не преобразует departureDate в московскую календарную дату.
- Внутренний ключ — отдельный ASCII-секрет не короче 32 символов из
  `INTERNAL_API_KEY`, отличный от токена Travelpayouts. Сравнение выполняется
  через `secrets.compare_digest`. Отсутствующий/неверный/повторяющийся ключ — 401.
- Передавать ключ только серверу Python по закрытой сети; при сетевом размещении
  использовать HTTPS на прокси или TLS между сервисами. В примере локального
  запуска сервер слушает только `127.0.0.1`. Пользовательский JWT Python не нужен.

## Успешный ответ

```json
{
  "source": "Aviasales",
  "dataType": "cached_offers",
  "currency": "RUB",
  "flights": [
    {
      "origin": "MOW",
      "destination": "LED",
      "departureDate": "2026-12-15",
      "departureAt": "2026-12-15T07:00:00Z",
      "airline": "SU",
      "flightNumber": "1234",
      "price": 4500.75,
      "currency": "RUB",
      "transfers": 0,
      "durationMinutes": 95,
      "bookingUrl": "https://www.aviasales.ru/search/example"
    }
  ]
}
```

Пример искусственный, не реальный билет. Полная машинная схема —
[openapi.json](openapi.json), та же схема доступна у сервера в `/openapi.json`,
Swagger UI — `/docs`. Схемы и `/health` доступны без ключа и не содержат секретов;
внешний доступ к самому сервису должен ограничиваться сетью/прокси.

| Поле | Тип и правило |
| --- | --- |
| `origin`, `destination` | Нормализованные коды запроса; проверяется соответствие маршрута источника, включая город и конкретный аэропорт |
| `departureDate` | Запрошенная дата вылета; известная дата источника должна совпадать |
| `departureAt` | ISO timestamp в UTC или `null`; исходный timestamp с явным offset переводится в UTC, для времени без offset часовой пояс не выдумывается |
| `airline`, `flightNumber` | Строки либо `null`; номер рейса сохраняет ведущие нули/буквы |
| `price` | Обязательное положительное конечное JSON-число, не более 2 знаков после запятой, в диапазоне .NET decimal; в C# использовать `decimal`, не `double` |
| `currency` | Всегда `RUB`; источник запрашивается в RUB, конвертации валют нет |
| `transfers` | Целое число ≥ 0 либо `null` |
| `durationMinutes` | Целое число ≥ 0 либо `null`; используется `duration_to`, с резервным `duration` только для предложения в одну сторону |
| `bookingUrl` | Проверенная ссылка HTTPS на `/search/...` у Aviasales либо `null` |

Ключ каждого поля предложения обязателен в JSON и в OpenAPI. У полей,
допускающих отсутствие сведений, значение равно `null`; ключ не пропускается.
`departureDate` может отличаться от календарной даты UTC в `departureAt`, если
преобразование часового пояса пересекло полночь. C# должен использовать
`DateOnly`, `DateTimeOffset?`, `decimal`, `int?` и nullable-строки соответственно.

Пустая выдача — **200** с теми же метаданными и `"flights": []`. Предложения
сортируются по числовой цене по возрастанию, порядок равных цен сохраняется.
Ответ поиска содержит `Cache-Control: no-store`; это не меняет кэшированную
природу данных источника. Сервис не хранит результат, поэтому `offerId` не выдаётся.

## Некорректные данные источника

Одна испорченная запись приводит к ошибке всего поиска 502, а не к частичному
списку или ложному пустому результату. Проверяются обязательные значения, типы,
маршрут, известная дата и RUB. Неожиданное предложение туда-обратно отклоняется.
Отсутствие необязательного поля допускается, неверный тип присутствующего — нет.

Ссылки строятся только для доменов `aviasales.ru`, `www.aviasales.ru`,
`aviasales.com`, `www.aviasales.com`. Относительный `/search/...` дополняется
`https://www.aviasales.ru`. Запрещены HTTP, другие домены/порты, userinfo,
фрагменты, управляющие символы, обратные слеши и переходы `..` в пути.
Python не открывает переданную ссылку; HTTP-клиент обращается только к фиксированному
API Travelpayouts и не следует редиректам с секретным заголовком.

## Ошибки

Тело всегда `{"code":"...","message":"..."}`. Обрабатывать нужно `code`,
а не сравнивать текст `message`. Сырой ответ/ошибка Travelpayouts и секреты
клиенту не возвращаются.

| HTTP | `code` | Причина |
| --- | --- | --- |
| 400 | `INVALID_SEARCH_PARAMETERS` | Параметры отсутствуют, неверны, повторяются или не поддерживаются |
| 401 | `UNAUTHORIZED` | Неверный/отсутствующий ключ C# → Python |
| 502 | `FLIGHT_PROVIDER_ERROR` | HTTP-ошибка провайдера, включая 401/429, редирект, невалидный JSON или данные |
| 503 | `FLIGHT_SERVICE_UNAVAILABLE` | Сбой соединения, настройки или исчерпание доступных слотов поиска |
| 504 | `FLIGHT_SEARCH_TIMEOUT` | Сетевой timeout провайдера |
| 500 | `INTERNAL_ERROR` | Непредвиденная внутренняя ошибка |

На неизвестном пути возвращается 404 `NOT_FOUND`, на неподдерживаемом методе —
405 `METHOD_NOT_ALLOWED`. Ошибки пользовательского JWT, прав и отсутствия поездки
обрабатывает C#; его публичные 401/403/404 не следует путать с внутренним 401.

По ответу Стаса C# нормализует публичные статусы: неверные параметры — 400,
ошибка провайдера — 502, недоступность — 503, timeout — 504. **Внутренний 401
Python преобразуется в публичный 502** как ошибка межсервисного взаимодействия.
Python продолжает отвечать 401 при неверном внутреннем ключе.

8 ноября получен ErrorCatalog_T-Travel.pdf: публичный C# использует ProblemDetails
с code; внутренний 401 преобразует в 502 FLIGHT_INTEGRATION_AUTH_ERROR,
нечитаемый/невалидный ответ Python — в 502 INVALID_FLIGHT_SERVICE_RESPONSE.
Сбой Python/Travelpayouts — 502 FLIGHT_PROVIDER_ERROR, в том числе внутренний
500 зависимости; собственный неожиданный сбой C# — 500 INTERNAL_ERROR.
Этот каталог не меняет внутренний code/message Python. Статус общего утверждения
и готовность реализации C# не подтверждены. [Разбор каталога](ERROR_CATALOG_REVIEW.md).

Пример `examples/csharp/FlightSearchClient.cs` сохраняет исходный статус Python
в `FlightSearchException.Status` для вызывающего C# кода. Он не является
публичным контроллером: этот статус нельзя автоматически пересылать frontend;
контроллер должен выполнить описанное выше преобразование.

## Таймауты, нагрузка и повторы

- Requests: connect timeout 3 с, read timeout 10 с, настраиваются через env.
  Read timeout — предел ожидания очередных данных, а не жёсткий предел всей операции.
- В C# примере общий `HttpClient.Timeout` равен 30 с и передаётся CancellationToken.
  Отмена запроса C# не прерывает уже выполняющийся синхронный запрос Python.
- По умолчанию одновременно выполняется не более 4 поисков на процесс Python.
  При заполнении слотов — 503 с `Retry-After: 1`. Отдельной очереди ожидания слота нет.
- Автоматических повторов нет. C# должен соблюдать общий бюджет запроса,
  ограничивать поток пользователей и не запускать бесконечные повторы.
  Согласовать политику повторов и лимит нагрузки с командой/лимитами провайдера.
- Для C# клиента отключить `AllowAutoRedirect`, чтобы ключ не пересылался по
  неожиданному редиректу. В Python автоматические редиректы отключены.

## Проверка и передача Стасу

1. Запустить сервис по README. `GET /health` проверяет только жизнь приложения,
   не доступность Travelpayouts. Без правильных ключей/справочника сервис не запускается.
2. Импортировать `docs/openapi.json` либо использовать `examples/csharp/FlightSearchClient.cs`.
3. Проверить ответы из `examples/responses/` — это явно искусственные примеры.
   `scripts/export_contract.py` обновляет их вместе со схемой без сети и реальных ключей.
4. Выполнить реальный запрос с будущей датой; пустой кэш — допустимый результат.
5. На C# проверить доступ к поездке, показать предупреждение об изменяемой цене,
   открыть ссылку и сохранить выбранный рейс вручную. При `bookingUrl: null`
   переход недоступен. Стас предложил разрешить ручное сохранение без ссылки;
   для этого source_url нужно сделать nullable после согласования с Матвеем.
   Наличие такой миграции и готового маршрута сохранения пока не подтверждено.

## Зафиксировано по ответу Стаса

- GET /internal/flights/search и origin/destination/departureDate, ответ flights[].
- X-Internal-Api-Key, общий секрет в конфигурациях вне репозитория, защищённая передача.
- Общий timeout C# 30 с, автоматические редиректы отключены.
- Без offerId в базовом MVP; будущие кэш/идентификаторы — ответственность C#.
- Все поля предложения присутствуют; отсутствующие необязательные сведения — null.
- Публичные статусы нормализует C#, внутренний 401 Python преобразует в 502.
- Для интеграционного тестирования приняты текущие параметры Python: временное
  правило Europe/Moscow, таймауты 3/10 с и лимит 4 поиска на процесс.

## Что ещё требуется перед совместной приёмкой

- Стас согласует с Матвеем репозиторий и готовность C# контроллера. Рабочая ветка
  интеграции пока не подтверждена; ожидаются коммит, запуск и тестовая поездка.
- Матвей должен согласовать предложение сохранять рейс без ссылки и изменение
  source_url на nullable; затем C# реализует миграцию и поведение интерфейса.
- Подтвердить принятие и реализацию публичного каталога ошибок с Матвеем/Стасом:
  ProblemDetails и правила преобразования описаны в полученном PDF, но наличие
  готового C# обработчика не подтверждено. Пример адаптера требует уточнения
  новых кодов (см. разбор каталога).
- Уточнить политику повторов и параметры для последующей эксплуатации по итогам
  интеграционного тестирования; текущие Europe/Moscow, 3/10 с и лимит 4 приняты
  для этого этапа. Автоматические повторы сейчас отключены.
- Настроить реальный адрес, защищённую передачу и общий секрет между сервисами.
- Выполнить совместный smoke-test: успех, пустая выдача, неверные параметры,
  внутренний ключ, timeout, права пользователя и ручное сохранение.

Links API, SubID, Statistics API и автоматическое добавление покупок относятся
к §3.6 и в этот базовый модуль не включены. Проект Travelpayouts для генерации
партнёрских ссылок не требуется для предусмотренной здесь исходной ссылки Aviasales.
