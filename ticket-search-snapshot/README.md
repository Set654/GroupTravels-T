# Авиамодуль «Т-Путешествие»

Python-клиент Travelpayouts / Aviasales Data API с проверкой параметров и ответа,
запуском из терминала и тестами без сетевых запросов.

Клиент возвращает кэшированные предложения. Цена и наличие на момент покупки
не подтверждаются. Сортировка по цене выполняется источником (`sorting=price`),
запрашивается до 10 предложений. Порядок полученного списка сохраняется.

## Установка

Проверено с Python 3.12. Команды для PowerShell, из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если `.env` ещё нет, создайте его из примера:

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

Заполните `TRAVELPAYOUTS_TOKEN` в `.env` либо задайте переменную окружения.
Переменная окружения имеет приоритет над `.env`. Настоящий токен нельзя коммитить.
В `.env.example` оставлено только пустое поле. `unittest` входит в Python;
Playwright для авиамодуля не требуется.

## Запуск вручную

Справка работает без токена и сетевого запроса:

```powershell
.\.venv\Scripts\python.exe main.py --help
```

Поиск в одну сторону:

```powershell
.\.venv\Scripts\python.exe main.py --origin MOW --destination LED --departure-at 2026-12
```

Туда-обратно, с сохранением непустого результата:

```powershell
.\.venv\Scripts\python.exe main.py --origin MOW --destination LED --departure-at 2026-12-10 --return-at 2026-12-20 --output tickets.json
```

Выберите нужные даты при запуске. Эти команды выполняют настоящий запрос,
для которого нужен токен. JSON-список выводится в терминал; файл создаётся только
при `--output`. Коды завершения: `0` — успешный поиск, включая пустую выдачу,
`1` — ошибка поиска/настройки/сохранения, `2` — неправильные аргументы командной строки.

Пустой список `[]` означает успешный поиск без предложений в кэше. При пустой
выдаче файл не создаётся и существующий файл не меняется. При непустой выдаче
указанный файл заменяется. Файл содержит параметры поиска, локальное время
`requested_at` и список `tickets`; это средство отладки.

## Использование как Python-модуля

```python
from main import get_cheap_bilets

tickets = get_cheap_bilets(
    origin="MOW",
    destination="LED",
    departure_at="2026-12",
    return_at=None,
)
```

Вызов возвращает список словарей источника либо поднимает исключение.
Пустая выдача отличается от ошибки. Данные билетов пока передаются без
согласованного с C# преобразования полей и денежных значений.

Правила аргументов текущего клиента:

- `origin` и `destination` — строки из трёх латинских букв для города/аэропорта.
  Пробелы по краям удаляются, буквы переводятся в верхний регистр. Существование
  кода в справочнике отдельно не проверяется; коды стран не входят в этот интерфейс.
- Даты — календарно корректные `YYYY-MM` или `YYYY-MM-DD`, с удалением пробелов
  по краям. Для одного направления `return_at=None`; пустая строка недопустима.
- Месяц означает весь месяц. Возврат отклоняется, если весь его период раньше
  начала периода вылета. Пересекающиеся периоды допускаются, например вылет
  `2026-12-20` и возврат `2026-12`. Оба фильтра передаются источнику как есть.
- Запрет прошедших дат и дополнительные продуктовые ограничения пока не вводились.

Ошибки можно различать по типам из `errors.py`:

| Тип | Причина |
| --- | --- |
| `SearchValidationError` | Неправильные аргументы поиска |
| `ConfigurationError` | Отсутствующий или пустой токен |
| `ProviderResponseError` | Неожиданная структура JSON источника |
| `ProviderSearchError` | Источник не подтвердил `success is True` |
| `requests.exceptions.Timeout` / `ConnectionError` | Сетевой сбой |
| `requests.exceptions.HTTPError` | HTTP-ошибка источника |
| `requests.exceptions.JSONDecodeError` | Ответ не является корректным JSON |

Сетевые исключения передаются вызывающему коду. Для запроса задан `timeout=10`
в терминах Requests; это не общий предельный срок выполнения всей операции.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
```

Запросы подменены, настоящий токен не используется. Проверки записи работают
с временными папками. Тесты покрывают клиент, валидацию, сохранение и терминальный
запуск; они не обращаются в Travelpayouts и не подтверждают наличие билетов.

## Граница готовности

HTTP-сервер FastAPI ещё не реализован. До него нужно согласовать входной и
выходной контракт, формат денег, HTTP-ошибки, внутреннюю авторизацию и таймауты:
[список вопросов для интеграции](docs/INTEGRATION_CHECKLIST.md).
Текущие CLI и Python-функция не являются утверждённым HTTP-контрактом.

Отели, развлечения и OCR в этом модуле не реализованы. Исторические эксперименты
в `litter/` не относятся к установке и проверкам авиаклиента.

Параметры источника сверены с
[официальной документацией Travelpayouts](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API).
